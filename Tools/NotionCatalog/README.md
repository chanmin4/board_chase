## 아이템 수집 기준

`node Tools/NotionCatalog/read-item-maker.cjs`는 읽기 전용 JSON 추출이다. Unity 에셋/프로필/노션을 직접 수정하지 않는다. ItemMakerWindow.RefreshItems의 두 경로를 사용하고, 스크립트 GUID와 C# 상속 관계로 ItemSO를 판별한다. 최초 193개, 비아이템 정의 제외 111개, 미확인 스크립트 0개였다.

일반 정보·이름 번역·기본 등급·가격·스택·사용레벨·상세 정의를 읽는다. Unity YAML 정적 스냅샷이며 AssetDatabase/Play Mode를 실행한 결과는 아니다. 현재 소스 기본값을 적용한 일부 요약은 원본/코드 변경 시 다시 확인해야 한다. 한국어 번역 우선, 영어 차선, 미등록이면 에셋 이름을 사용한다. 테스트·WIP 및 중복 표시 이름도 누락시키지 않는다. 원본 하나가 여러 패시브 등급을 지원하면 한 행 안에 등급별 범위를 기록한다.

## 다음 갱신 시

1. 사용자가 문서 갱신을 요청했을 때만 실행한다. 자동 동기화/반복 작업은 없다.
2. 실제 Item Maker의 검색 범위와 분류 코드, 사용 레벨 원본을 재확인한다.
3. 기존 데이터 소스 스키마/뷰를 읽고 GUID로 대조한다. 새 데이터베이스나 같은 GUID의 행을 중복 생성하지 않는다.
4. 기존 사용자의 변경메모·기획 본문을 보존한다. 원본 필드/기준일만 갱신하고 차이를 보고한다.
5. 사라진 원본은 바로 노션/Unity에서 삭제하지 말고 ‘제거됨’ 또는 검토 표시로 구분한다. 노션의 추가/제거 계획은 Unity 실제 변경 권한이 아니다.
6. 모든 페이지를 페이지네이션해 총수·GUID 유일성·분류/수치 일치를 검증한다.

## 2026-10-29 아이템 목록 갱신 및 기획 입력 틀

- 기존 DB/행을 재사용했다. 기존 193개 갱신 + 감염 잠식 회복 주사기/학습 촉진 2개 추가 = 현재 원본 195개, GUID 195개. 누락·중복·원본 대조 불일치 0개, 제거 대상 없음.
- `node Tools/NotionCatalog/prepare-item-refresh.cjs`는 기존 읽기 전용 수집기에 현재 Valuable 분류/전투·생존 패시브 분류/요약/현재 Quest SO 참조를 더한다. `--summary`는 개수만 요약한다. Unity 에셋·노션·파일을 직접 쓰지 않는다.
- Item Maker 검색 범위와 동일한 두 폴더, 비아이템 제외 111개, 미확인 스크립트 0개. 테스트·WIP 원본도 목록에 유지한다.
- **사용자 영역**: 제목, 기획설명, 기획가격, 퀘스트메모, 교환메모, 변경메모, 설계상태. 다음 갱신 시 절대 원본 값으로 덮어쓰지 않는다. 이번 최초 추가 때만 설계상태를 미작성으로 초기화했다. 기획가격/기획설명은 195개 모두 빈칸으로 두었다.
- **원본 스냅샷 영역**: 기본가격, 현재설명, 현재표시명, 현재퀘스트사용, 분류/세부분류/물품분류, 등급, 최대스택, 사용레벨, GUID/원본경로, 기준일. 현재 사용 레벨을 우회하는 패시브는 1로 기록하며 슬롯 해금 레벨과 구분한다.
- 기존 193개 카드 본문을 모두 읽은 뒤 생성된 원본 정보와 안내 문장만 정확 일치로 갱신했다. 기획 메모와 원본 식별/상세 내용을 통째로 지우지 않았다. 모든 카드에 NPC·스테이지·수량·선행/후속·보상을 적는 아이템별 퀘스트 틀과 교환/공급 작성 틀이 있다.
- `현재퀘스트사용`은 GameScene 내 QuestDefinitionSO 38개에서 `_targetItem`, `_requiredWeapon`, 아이템 보상 참조만 정적으로 수집한다. 템플릿은 표시하며, 실제 QuestLine 활성화/노션 기획 전체/런타임 도달 여부까지 증명하는 필드가 아니다.
- Valuable 45개는 이번 분류를 반영했다: 도구 9, 건설자재 4, 의료물품 1, 생활품 10, 전자부품 3, 식료품 9, 수집품 8, 미분류 1. 군용물품 옵션은 있으나 배정 아이템은 없다.
- 기존 프로젝트 페이지의 연결 DB에서도 **설명·가격 작성 / 아이템별 퀘스트 / 귀중품 물품분류** 탭을 쓸 수 있다. 원본 DB에도 같은 3개 보기를 추가했다. 추가·변경·제거 및 WIP 등 기존 보기는 보존했다.
- 최종 전체 행을 두 구간(100+95)으로 다시 조회하여 195개 GUID/분류/물품분류/가격/스택/등급/사용레벨/현재 이름·설명/퀘스트 참조/기준일을 대조했다. 원래 제목·변경메모도 보존 확인했다. 본문 갱신은 193개 성공 응답, 신규 페이지는 2개 성공 응답으로 확인했다.
- 노션 API 제한 시 `retry_after_seconds`를 지키고, 완료 ID를 기록한 뒤 실패/미처리 항목만 재개한다. 한 번의 SQL 응답이나 `has_more=false`만으로 전체 수집을 단정하지 말고 개수와 GUID 전체를 대조한다.
- 노션 편집은 Unity에 자동 적용되지 않는다. 이번 요청으로 게임 코드·아이템 가격·실제 퀘스트 설정을 수정하지 않았다.

## 퀘스트 연결도 (2026-10-28 기록)

기존 Miro 빈 양식은 보존했다. 새 6개 프레임은 Stage 1 메인, Stage 2 메인, 장비/상점/분해 해금, 전투/탐험 서브, Stage 3~6 초안, 미배정 후보이다. 각 프레임 2000×1500이며 수정 가능한 Mermaid 다이어그램을 포함한다. 계정의 개별 도형형 생성 미지원은 우회하지 않았다.

실선은 원문 기능·행동·보상 관계이고 점선은 검토용 순서/후보이며, Quest SO의 실제 선행 등록 증거가 아니다. ONCE/RUN/REPEAT 및 여러 선행의 AND/OR를 임의 확정하지 않았다. 같은 ‘싸움의 필수품 1’ 반복은 한 노드로 묶었고, 서로 목표가 다른 두 ‘특별한 힘’은 구분했다. 원문 퀘스트 본문은 보존했다.
