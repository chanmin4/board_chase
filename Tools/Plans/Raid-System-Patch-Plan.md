## 1. 확정된 공간 규칙

기획 좌표는 사용자가 설명한 **1~N**, 오른쪽이 +X, 위쪽이 +Y다. Unity의 기존 그리드 계산은 **0~N-1**이므로 변환을 한 곳에서 처리한다.

- N은 홀수, M = (N-1)/2, 기획상 중앙 C = M+1.
- 내부 좌표 중앙은 (M,M). 예: 7×7 중앙 기획 (4,4) = 내부 (3,3).
- 해치방: 정확히 중앙 한 칸, 전용 섹터/프리팹 사용.
- 발전소: 좌상단 또는 우하단 사분면 중 **한 곳에 한 개**. 두 군데 모두 생성하는 의미가 아니다.
- 보스방과 일반 탈출방: 우상단 사분면에서 서로 다른 두 칸 선택.
- 중앙 행과 중앙 열은 발전소/보스/일반 탈출방의 후보에서 제외한다. 이 행·열 자체를 없애거나 통행 금지하는 의미는 아니다.
- 각 사분면의 M×M은 후보 영역 크기이며, 보스방이 M×M 칸을 차지하는 의미가 아니다.
- 발전소와 일반 탈출구는 처음부터 지도에 표시한다. 보스 표시는 보스 등장 규칙과 일치시킨다.
- 발전소 가동 후 해치 탈출 마커를 공개한다. 중앙 위치 자체는 규칙상 추론 가능하므로, '위치 비밀'과 '탈출 마커/사용 가능 상태 비공개'를 구분한다.

| 스테이지 | 맵 N×N | 중앙(기획 좌표) | 후보 영역 M×M |
|---|---|---|---|
| 1 | 7×7 | (4,4) | 3×3 |
| 2 | 9×9 | (5,5) | 4×4 |
| 3 | 11×11 | (6,6) | 5×5 |
| 4 | 13×13 | (7,7) | 6×6 |
| 5 | 13×13 | (7,7) | 6×6 |

| 대상 | X 범위(기획) | Y 범위(기획) |
|---|---|---|
| 발전소 후보 A: 좌상단 | 1~M | C+1~N |
| 발전소 후보 B: 우하단 | C+1~N | 1~M |
| 보스/일반 탈출: 우상단 | C+1~N | C+1~N |
| 해치 | C | C |

7×7 예: 발전소 (X 1~3,Y 5~7) 또는 (X 5~7,Y 1~3), 보스/일반 탈출 (X 5~7,Y 5~7).
9×9 예: 발전소 (X 1~4,Y 6~9) 또는 (X 6~9,Y 1~4), 보스/일반 탈출 (X 6~9,Y 6~9).

일반 탈출구의 시작점 최소거리는 실제 방 연결 경로 기준으로 검사한다. 후보 중 가능한 칸을 먼저 구하며, 불가능한 설정은 무한 재추첨하지 않고 검증 오류로 알린다.

## 2. 현 코드에서 확인한 변경 지점

- `StageMapGenerator.GenerateFullGrid`: 보스 목표 좌표가 (N-1,N-1)로 고정되어 있다.
- 같은 파일의 `AssignSingleOuterExtraction`: 일반 탈출을 위쪽/오른쪽 **최외곽 포털** 중 하나로 고른다. 새 우상단 영역은 내부 칸도 포함하므로, 기존 외곽 포털만 이동해서는 요구사항을 충족할 수 없다.
- `StageMapLayout`: 단일 goalRoomCoord와 단일 extractionSectorCoord/extractionDirection 모델이다. 중앙 해치·조건부 탈출·선택적 보스 상태를 표현하도록 확장이 필요하다.
- `StageDefinitionSO`: 필수 보스 목표 구조와 선택적 branch topology가 있다. 기존 수작업 topology를 삭제하지 않고 새 홀수 정사각 정책과 명시적으로 분리해야 한다.
- `StageSectorInstantiator`: 기본 Start Sector는 (-1,0), 첫 생성 방은 (0,0)이다. 사용자의 '시작 (0,0)'과 현재 별도 시작 허브를 같은 대상으로 취급하지 않는다.
- 현재 Stage1~5 SO의 `_roomGridSize`는 3/4/4/5/5다. 새 규칙 코드가 준비된 후 7/9/11/13/13을 적용한다.
- `StageRoomType`에는 기존 Normal/Boss 외 Named/Treasure/Shop/BigMonsterWave 등의 직렬화 값이 있다. 값 재배열/재사용 없이 신규 역할을 추가하거나 별도 콘텐츠 역할로 분리한다.
- `SectorRoomTraitRuntime`에 기존 생화학 가스/방 타이머 실패 누적 경로가 있다. 레이드 가스를 두 번째 독립 피해 루프로 중복 생성하지 않는다.
- `QuestDefinitionSO`에는 StageUnlock/ShopUnlock/Stat/WarehouseSlots 보상이 이미 있다. 보상 시스템을 새로 만들기보다 해당 경로를 재사용한다.
- `PlayerRunStateSaveData`에는 인벤토리/체력/장비/상점 등의 스냅샷이 있지만, 이번 계획의 맵 배치·발전소 전력·전체 레이드 시계 필드는 없다. 기존 세이브 계층에 추가하고 마이그레이션해야 한다.

위 목록은 이번 계획 작성 시 읽은 코드 기준이다. 전체 프로젝트 실행 상태를 새로 감사했다는 의미는 아니다.

## 4. 각 단계의 구현 계약

### P01~P03: 생성·배치

- 역할과 콘텐츠를 구분한다. '일반 탈출 기능'이 붙었다고 무조건 이웃 방 연결을 끊지 않는다.
- 시작/해치/발전소/보스/일반 탈출 좌표를 우선 예약한 후, 남은 칸에 일반방·무기고·의무실·금고를 배정한다.
- 전용 생성 정책을 선택하면 branch topology가 이 정책을 몰래 덮어쓰지 않게 한다. 기존 topology는 WIP/호환 경로로 보존한다.
- 배치, 보스 출현, 방 콘텐츠 등에 독립적인 seed 분기를 사용한다. 콘텐츠 추첨 호출 하나 추가했다고 이미 정해진 발전소 위치가 달라지지 않게 한다.
- 저장은 seed만 의존하지 않는다. 생성 버전과 확정 배치/상태를 보관하여 로드 중 다른 맵이나 다른 보스 출현 결과로 바뀌지 않게 한다.
- 7×7 한 스테이지에서 먼저 실제 이동/탈출까지 연결한다. 13×13은 데이터 규칙 테스트를 먼저 하고 마지막에 실제 성능과 활성 섹터 수를 확인한다.

### P04~P06: 탈출·전력·시간

- 일반 탈출은 '보스 클리어 후 다음 스테이지 이동'과 다른 성공 조건이다. 기존 보스 목표에 묶인 문/스테이지 종료 소비자를 모두 찾는다.
- 보스방과 일반 탈출방은 겹치지 않는다. 보스가 없더라도 일반 탈출을 막지 않는다.
- 발전소는 지도에 처음부터 표시한다. 위치 공개가 주변 모든 방/적/상자 공개를 뜻하지는 않는다.
- 전력 가동은 배터리 소유 확인→상태 전이와 소모 확정→저장→표시/알림의 한 거래로 처리한다. 연타·중복 이벤트·로드로 두 번 차감하거나 배터리 없이 가동되지 않게 한다.
- 해치는 정확히 중앙에 고정한다. 위치/역할을 일반방 추첨으로 바꾸지 않는다.
- 전체 레이드 시계는 방 이동 시 재시작하지 않는다. 일시정지/메뉴/오프라인 경과 정책은 명시한다.
- 방 가스와 전체 레이드 가스는 기존 노출·가스마스크 시스템에 입력한다. 초당 피해 루프를 복제하지 않는다.
- 사용자 확정: 시작 허브는 외부 (-1,0), 첫 맵 방은 (0,0). 허브의 귀환 탈출은 정식 기능이며 잘못 선택한 스테이지/Stage3 가스 적응을 위한 탈출이다. 일반 탈출방 한 개와 별개다.
- Stage3+ 특별 탈출구는 중앙 해치와 별개다. 이번에는 비활성 WIP 설정/종류만 남기고 실제 탈출 지점이나 조건은 만들지 않는다.

### P07~P08: 방 역할·전투

- 무기고: 무기/탄약 상자 + 중무장 적.
- 의무실: 의료 상자 + 일반방 수준의 기본 적 구성.
- 일반방: 혼합 파밍.
- 금고방: Valuable/자금 중심. 잠금 방식은 콘텐츠 수치 확정 때 결정한다.
- 보스방: 스테이지 보스와 전용 전투 공간. 실더는 방패 계산 완료 이후 연결한다.
- 발전소/해치방: 해당 상호작용이 다른 프리팹 편집으로 누락되지 않도록 작성 도구 검증 항목을 둔다.
- 사용자 확정: 실드는 전방위 추가 방탄이다. 실드 → 장착 방탄복 → 엔티티 기본 방탄의 세 계산을 차례로 적용한다. 방어등급 합산이나 방향 판정은 하지 않는다.
- 방패와 방탄이 각각 피해를 낮추면 최종 감소 폭은 더 커진다. 두 계산의 바닥값과 내구도 소모를 함께 테스트한다.
- 기존 플레이어 고정 근접 피해 5의 방탄 무시 계약을 유지한다. 이번 실드는 물리 충돌 방패가 아니라 방탄 계층이므로 고정 근접은 실드와 그 내구도도 우회한다.

### P09~P10: 진행과 경제

| 진행 구간 | 자격 증명 | 다음 개방 |
|---|---|---|
| Stage1 | Normal Valuable 10개 제출 | Stage1 보스 처치 + 자금 → Stage2 |
| Stage2 | Rare Valuable 제출 | Stage2 보스 처치 + 자금 → Stage3 |
| Stage3 | Unique Valuable 제출 | Stage3 보스 처치 + 자금 → Stage4 |
| Stage4 | Legendary Valuable 제출 | Stage4 보스 처치 + 자금 → Stage5 |
| Stage5 | 최종 조건 미정 | 특별맵 개방 / 엔딩 |

- P09/P10 범위 축소: RaidProgressionDraft_WIP에 등급/수량/보스/금액/다음 Stage 및 서브 퀘스트 선행 조건을 기록한다. 기존 QuestDefinitionSO 연결 칸만 두며 실제 제출/금액 차감/자동 해금은 이번에 활성화하지 않는다.
- 등급별 Valuable 실제 제출은 후속 구현이다. 기존 CollectItem의 보유량 판정을 제출/소모와 같은 기능으로 취급하지 않는다. 미정 수량/금액 0은 공짜 완료가 아니라 미정 값이다.
- 보스 등장 65%는 기본 규칙이다. 앞서 제안했던 메인 퀘스트 중 확정 등장/미등장 보정은 아직 사용자의 명시 확정이 없으므로 자동 추가하지 않는다.
- 창고 확장은 메인 또는 전용 퀘스트 보상으로 지급, 난도는 중상. 기본 슬롯/단계별 증가량은 추후 수치화한다.
- 장비 해금: 방탄 Lv2 별도 스테이지 선행 없음, Lv3 Stage2 개방 후, Lv4 Stage3 개방 후. Lv5~6은 후속 데이터로 정한다.
- 소비품/탄약 해금과 영구 스탯 증가는 별도 서브 퀘스트. 주사기 해금 선행은 Stage3 개방.
- Lv1~6까지만 일반 해금, Lv7~8은 특수 파밍 전용. '해금=상점 구매 해금'인지 사용/장착 제한까지 의미하는지는 P10 전에 확정한다.
- 기존 퀘스트의 완료 기록/보상 ID를 새 퀘스트 의미로 덮어쓰지 않는다. 교체/폐기/마이그레이션을 구분한다.

## 5. 세이브·UI·테스트 공통 요구

매 단계에 포함할 항목:

- 신규 enum 값 뒤에 추가, SO/GUID 보존, 구형 데이터 기본값 및 schema migration 검증.
- 레이드 seed/배치 버전, 확정 특수방 좌표, 보스 출현·처치 상태, 발전소 가동, 해치 공개/활성 상태, 시간·가스 상태, 탈출 확정 상태를 소유자별로 저장.
- 영구 스테이지/퀘스트/창고/구매 해금은 profile, 진행 중 레이드 상태는 run으로 분리한다.
- 배터리 소모, 탈출 정산, 퀘스트 제출/보상은 중복 이벤트에 안전하게 처리한다.
- UI 표시 문구는 기존 Localization Table의 KO/EN에 함께 추가하고, 효과음은 기존 AudioCue 경로에 연결한다.
- 신규 조건/좌표/가스 상태는 기존 작성 도구와 Save Inspector에서 확인 가능하게 한다. 새로운 거대 통합 에디터를 만들지 않는다.

최종 검증 목록:

1. Stage1~5 각각 1,000개 seed 자동 검사: 해치 중앙, 발전소 한 개, 영역 준수, 보스/탈출 중복 없음, 필수 경로 접근 가능.
2. 보스 등장 확률 0/65/100% 경계와 결정론 검증. 65% 표본 비율을 정확히 650/1,000으로 강제하지 않는다.
3. 배터리 없음/충분함/연타/이미 가동됨/재로드의 가동·소모 검사.
4. 일반 탈출, 해치 탈출, 조건 미충족 특별 탈출, 중복 탈출 요청, 사망 중 탈출 요청 검사.
5. 방 이동·일시정지·재로드와 레이드 시계/가스 상태 검사.
6. 방패→방탄, 방패 우회, 방패 파괴, 방탄 파괴, 고정 근접, 일반 탄환의 피해 회귀 검사.
7. Valuable 혼합 스택 제출, 자금 소모, 스테이지 해금, 창고/스탯 보상 중복 방지.
8. 인벤토리 정렬 전후 아이템별 GUID/수량/내구도/상태 동일성 검사.
9. 구형 세이브 로드, 저장 중단 복구, 탈출/퀘스트 보상 후 재로드 검사.
10. 13×13에서 생성 시간, 활성 오브젝트/AI 수, 메모리, 미니맵 성능을 측정한 뒤 콘텐츠를 확대한다.

## 7. 첫 실행 범위

초기 계획은 P00~P02 분리 검증이었으며 사용자 요청으로 P00~P11까지 순차 적용한다.

완성 목표는 '7×7/9×9/11×11/13×13에서 중앙 해치와 각 후보 영역, 서로 겹치지 않는 특수방 좌표를 안정적으로 생성하고 저장 형식까지 정의한다'다.

그다음 P03~P05에서 7×7 한 스테이지를 실제로 생성해 **스폰→배터리 확보→발전소 가동→중앙 해치 탈출**, 그리고 **일반 탈출**의 두 경로를 완주한다. 이 경로가 안정된 뒤 가스·콘텐츠·퀘스트·수치 조정으로 확장한다.
