# Loot Maker — 2026-09-23

2026-09-29 후속 개편: 프리팹 등록, 독립 복사/붙여넣기, 공유 연결, 실제 썸네일 참조 보정을 추가했다. 최신 사용법과 검증은 `Loot-Maker-Authoring-2026-09-29.md` 참고. 아래는 최초 개편 기록이다.

## 적용 범위

기존 Loot Progression Table의 표시 이름과 메뉴를 **Loot Maker**로 변경했다.
메뉴: `Tools > Authoring > Loot Maker`. Item Maker와 Sector Maker의 바로가기도 같은 이름을 사용한다.
저장된 에디터 레이아웃과 기존 호출을 보존하기 위해 클래스/스크립트 이름 `LootProgressionEditorWindow` 및 GUID는 유지한다.
Enemy Drops의 스테이지별 드롭 구조는 변경하지 않았다.

## 데이터 구조

`카테고리 → 컨테이너 가족(LootObjectTypeSO) → 공통 아이템 목록(LootTableSO)`

각 가족의 외형별 `LootObjectSO`는 같은 테이블을 참조하되 다음 값은 따로 가진다.

- Inventory Slots: 컨테이너 인벤토리 칸 수.
- Size Label: Custom / Small / Medium / Large. 모델 크기를 변경하지 않는 작성용 분류.
- Override Table Rolls: 켜면 이 컨테이너만의 최소/최대 추첨 횟수를 사용한다. 끄면 공유 테이블의 기본 횟수를 사용한다.
- Success Per Roll (%): **매 추첨 시 아이템이 나올 확률**. 컨테이너 자체가 맵에 생성될 확률이 아니다.

따라서 작은 가방과 큰 가방 모두 Backpack 테이블을 읽으면서, 서로 다른 칸 수·추첨 횟수·성공률을 사용할 수 있다.
카테고리는 정리/검색용이며 아이템 종류를 강제로 제한하지 않는다. 필요하면 같은 카테고리 안에 여러 가족/테이블을 생성할 수 있다.

## 기존 컨테이너 연결

| 카테고리 | 연결 수 | 기존 LootObjectSO 이름 기준 |
|---|---:|---|
| Ammo | 1 | AmoBox_01 |
| Medical | 3 | HealthBox_01–03 |
| Military Gear | 7 | MilitaryCase 5종 + WeaponBox 2종 |
| Treasure Box | 2 | RareLoot_01 + LootChest_Template |
| Safe | 4 | Safe_01–04 |
| Backpack | 6 | SM_BackPack_19–24 |
| Metal Box | 5 | SM_Props_MetalBox_06–10 |

위 합계는 기존 GameItem/Loot 폴더의 28개 레코드다. 다른 위치의 레이드 전용 레코드는 재분류하지 않았다.
EnergyBox_01은 게임상 용도를 임의 결정하지 않고 Unassigned에 남겼다.

Ammo / Backpack / Safe는 기존 가족과 공유 테이블 GUID를 그대로 유지했다.
Medical / Military Gear / Treasure Box / Metal Box에는 각각 가족과 공유 테이블을 새로 만들었다.
새 테이블의 아이템 목록은 빈 상태이며, 기존 테이블의 아이템 목록은 변경하지 않았다.
기존 개별 fallback 테이블, 프리팹 연결, 표시 이름 및 슬롯 수(이 폴더의 기존 컨테이너는 6칸)는 보존했다.

## 작성 순서

사용성을 위해 Item Maker와 같은 3단 구조로 다시 정리했다. 왼쪽은 **분류**, 가운데는 **실제 상자 카드**, 오른쪽은 **선택한 상자의 편집창**이다. 이전의 가족 카드 목록/전체 프리팹 라이브러리/Add To Type 단계는 기본 화면에서 제거했다.

1. 왼쪽 **Categories**에서 분류를 누른다. 가운데 **Containers**에는 해당 분류의 상자만 표시된다.
2. 가운데 **상자 카드**를 한 번 누른다. 이름은 연결된 프리팹의 실제 이름을 우선 표시한다. 실제 이름/기존 표시 이름/SO 이름으로 검색할 수 있다.
3. 오른쪽 **Loot Items**에서 아이템 목록을 작성한다.
   - Item Maker 또는 Project에서 여러 ItemSO를 드래그하여 드롭 영역에 놓는다.
   - 각 아이템의 rarity에 맞는 항목으로 추가된다. 이미 있는 아이템은 중복 추가하지 않는다.
   - 한 번에 나오는 수량 Min / Max와 같은 rarity 안의 Manual Share를 조정한다.
   - 원본 ItemSO나 폴더 위치는 수정하지 않는다.
   - 아이템 선택 칸과 **+ Add** 버튼으로 하나씩 추가할 수도 있다.
   - 기본 화면은 아이템/수량 중심이다. **Edit individual item chances**를 켜면 Custom Share / Share in Tier로 비율을 조정할 수 있다.
   - 공유 목록 이름과 실제로 같은 테이블을 쓰는 상자 수를 표시한다. 펼치면 해당 상자 이름도 확인된다.
4. 오른쪽 **Box Settings**에서 칸 수·최소/최대 추첨 횟수·매회 생성 확률을 조정한다. **Small / Medium / Large** 버튼은 한 번 누르면 해당 프리셋을 즉시 적용한다.
5. 상단 **Save**를 누른다. Inspector 변경과 마찬가지로 Undo를 지원한다.

프리셋은 다음 시작값을 명시적으로 적용한다. 선택한 변형 하나만 변경하며 확정 밸런스가 아니다.

| 프리셋 | 칸 수 | 추첨 횟수 | 각 추첨 성공률 |
|---|---:|---:|---:|
| Small | 4 | 1–3 | 65% |
| Medium | 8 | 2–5 | 80% |
| Large | 12 | 4–8 | 90% |

단순히 카드를 선택하거나 검색/분류를 바꾸는 것만으로 데이터가 변경되지는 않는다. Custom은 직접 설정한 값이다.
목록 연결 변경은 **Box Settings → Advanced: Category / Loot List → Shared Loot List**에서 한다. 목록이 없는 상자는 연결 선택지를 즉시 표시한다. 새 공유 목록 생성과 개별 가족 관리는 왼쪽 **Advanced: Loot Lists**에 모았다.
UI 문구는 Item Maker처럼 짧은 영문으로 통일했다. 임시 Unity 검증에서 긴 한글 안내문에 따른 에디터 폰트 아틀라스 생성 Assert가 확인되어, 새 안내문은 영문으로 작성했다.

## 런타임 규칙과 기존 동작 보존

- 기존 변형은 기본적으로 테이블의 추첨 횟수 및 100% 성공률을 사용한다. 기존 시드 난수 소비 순서도 보존한다.
- 횟수는 먼저 정한 뒤 각 시도의 성공 여부를 판정한다. 실패한 시도는 아이템을 만들지 않는다.
- 기존 잠금 보상 프로필의 추가 추첨과 rarity 배율을 유지한다. 성공률은 보너스 추첨에도 적용한다.
- 기존 공통 rarity 가중치 Normal 63 / Rare 30 / Unique 6 / Legendary 1을 유지한다. 빈 rarity는 추첨 후보에서 제외되므로 실제 결과 비율은 채워진 목록과 잠금 배율에 따라 달라진다.
- 테이블에 유효한 항목이 있는데 모든 시도가 실패했다면 **정상적인 빈 상자 결과**다. rolled 상태와 빈 목록을 저장하여 다시 열거나 이어하기해도 재추첨하지 않는다.
- 테이블 자체가 비어 있거나 모든 항목의 유효 가중치가 0이면 설정 미완료다. 경고를 남기고 수색 준비/키 소비를 진행하지 않는다.
- 추첨 결과가 칸 수를 넘으면 기존 스택 합치기 및 월드 드롭 fallback을 따른다. UI에 경고를 표시한다. 아이템 수량과 아이템 슬롯 수는 동일 개념이 아니다.
- 프리팹 생성 빈도, 섹터 배치, 적 드롭, ItemSO 분류, 퀘스트 및 레이드 배치는 변경하지 않았다.

## 검증

- 프로젝트의 Unity 6000.0.47f1 / Roslyn 응답 파일로 런타임 및 에디터 전체 컴파일 성공. 런타임에는 기존 TMP obsolete/unused-field 경고 15개가 남는다.
- UI 개편 후 별도 임시 Unity 프로젝트에서 동일 소스를 컴파일한 회귀 테스트 **25/25 통과**.
- 별도 Unity 에디터의 실제 IMGUI 창에서 1060×600 / 1180×840 / 1600×900 크기와 두 탭을 검증했다. 20회 GUI 렌더링 처리에서 오류·Assert 0개, 외부 레이아웃의 창 영역 초과 없음. 이는 자동 레이아웃 검사이며 사용자 프로젝트 화면의 육안 검수나 실제 드래그 입력 전체 검증을 대신하지 않는다.
- 테스트: 공유 테이블 독립성, 각 크기 프리셋, 기본 시드 호환, 0/100%·0회 추첨, 확률 재현성, 잠금 보너스, 값 정규화, 빈 결과 저장/복구, 미설정 테이블, 다중 아이템 추가/중복 방지.
- 새 필드가 없는 기존 형식의 YAML asset을 Unity AssetDatabase로 실제 임포트하여 기존 슬롯과 기본 확률이 유지됨을 확인했다.
- 에디터가 접근하는 SerializedProperty 경로도 검증했다.
- 카테고리별 상자 필터링, 기타/목록 미연결 분리, 실제 프리팹 이름 검색, 서로 다른 가족이 같은 테이블을 쓸 때의 공유 개수, 카드 선택 시 올바른 테이블로 전환되고 데이터는 변경되지 않는 동작을 추가 검증했다.
- 기존 테이블/메타/프리팹 참조/슬롯 보존 및 28개 가족 연결과 신규 GUID 중복 여부를 확인했다.
- 테스트 파일: `Assets/Tests/EditMode/Editor/LootMakerTests.cs`.
- 실제 사용자 프로젝트의 창을 열어 화면 배치를 육안 확인하거나 게임 플레이 전체를 돌리지는 않았다. 임시 테스트 프로젝트만 실행했으며 기존 작업 씬/세이브는 열거나 저장하지 않았다.
