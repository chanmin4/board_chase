# Stage Maker 구현 / 검증 경계

## 열기와 기본 사용

Unity 메뉴 `Tools > Authoring > Stage Maker`. StageDefinitionSO Inspector 위에도 열기 버튼이 있다.

왼쪽은 Stage SO 목록/검색/번호순·이름순, 가운데는 넓은 단일 설정 화면, 오른쪽은 임시 맵 미리보기다. 기존 6개 탭은 없애고 모든 설정을 한 스크롤 화면에 모았다. 두 구분선을 드래그하거나 상단의 설정 넓게/지도 넓게 버튼으로 폭을 조정한다. 목록과 지도를 각각 숨길 수 있으며, 둘 다 숨기면 설정만 전체 폭으로 쓴다.

1. Stage SO를 선택한다. 기존 Stage1~6의 격자·확률·풀은 이 패치에서 바꾸지 않았다.
2. 설정 아래 고정된 `랜덤 생성` 또는 `현재 시드로 생성`을 누른다. 시드와 반복 검사 횟수는 왼쪽의 접힌 `테스트 옵션 · 시드 검증`에 있다.
3. 지도에서 우클릭 드래그로 이동하고 휠로 마우스 위치 중심 확대/축소, `맞춤`으로 전체 구조를 본다.
4. 확대하면 각 방 아래 종류와 선택된 SectorPreset 표시명이 나온다. 좌클릭하면 좌표·시작점 경로 거리·연결 방향·실제 Sector SO/프리팹/Encounter·잠금 상태를 본다.
5. 청록 선은 실제 포탈 연결이다. 인접해도 연결되지 않은 방 사이에는 선을 그리지 않는다. 노랑 선은 외곽 탈출 포탈, 빨강 방은 누락된 콘텐츠 참조다.
6. `연속 시드 검증`은 지정 시드부터 순차1~1000개를 확인한다. 한 편집기 업데이트에1개씩 처리하고 중단 가능하다. 실패한 시드/이유, 방 수 최소·최대·평균, 종류별 평균을 표시한다. 구조 성공과 콘텐츠 오류를 따로 센다.

설정을 바꾸면 기존 지도를 이전 결과로 표시하며 자동 재추첨하지 않는다. 지도 생성은 씬·프리팹·SO·저장 파일을 생성/수정하지 않는다. UnityEngine.Random도 소비하지 않는다. 섹터 내부3D 배치나 런타임 전술 미니맵의 장애물 모양을 렌더링하는 도구가 아니라, 실제 방 그래프와 프리팹 배정을 보는 도구다.

## 한 화면의 설정 구역

1. 맵 크기 · 생성 규칙: 격자, 밀도, 연결, 후보 거리/수, 탈출구, 보스, 상인. 스테이지 정보/생성 방식과 링/방 수 Override는 안쪽 고급 항목으로 접었다.
2. 등장할 맵 · 특별방: 기존 2개 탭에 나뉜 일반/전용/공용 풀과 특별맵 종류를 한 곳에 모았다. 특별맵은 한글 이름과 최소~최대 수량을 카드 제목에서 보여준다. 거리/방향/잠금/퀘스트/저장 ID는 각 카드의 고급 항목이다. 기존 별도 금고 확률도 이 구역에 모았다.
3. 전투 · 진행 · 환경: 필수방/전투와 해치/시간/환경/보급 설정을 합쳤다. 기본은 접힌 상태다.

테스트 옵션과 전체 원본은 아래 별도 접이식 항목이다. 영어 런타임 Header가 섞이지 않게 주요 단일 값은 한글 컨트롤로 그린다. 고급 전체 원본은 기존 Inspector와 같은 필드를 유지한다. 지도는 반복 검사/시뮬레이션 입력칸을 제거하고 구조를 크게 보여주며, 방 상세/오류 로그도 접을 수 있다.

### 제공하는 설정 항목 (기존 기능 유지)

- 기본·생성: 번호/표시명/WIP, 생성 정책/정사각 격자/시작방 모드/테마, 밀도/추가 연결/원거리 후보/탈출 수/후보 최소 거리/상인 수/보스 확률/기존 금고 확률.
- 고급 Override: 목표·최소·최대 방 수, 중심 링 반경 또는 비율, 후보 분산·시작거리 점수 가중치, 금고 후보 거리, 상인 최소 시작 거리. OFF면 기존 기본값을 사용한다.
- 맵 풀·비율: 새 구성 ON/OFF, 전용20·특별30·공용50 기본 목표, 전용/공용 프리팹 풀과 기존 Normal 대체 풀. 실제 에셋은 OFF를 유지했다.
- 특별맵: 추첨 ON/OFF, 전체 추첨 최소/최대, 종류 반복, 변형 프리팹 우선 중복 회피. 종류별 사용/ID/가중치/최소·최대/시작 경로 거리/방향/열쇠·잠금/퀘스트 보장/변형 목록.
- 필수방·전투: 역할별 변형/전투/루팅 참조, 보스 전투+맵 쌍, 일반 Encounter, 시간제한, 발전실 아이템, 금고/상인 설정.
- 환경·진행: 해치 다음 스테이지/선행 퀘스트, 원정 시간·감염·가스·이상현상·추가 보급.
- 전체·고급: 그 밖의 모든 직렬화 필드. Legacy/WIP 값은 현재 정책에서 사용하지 않을 수 있음을 표시한다.

프리팹 후보는 SectorPreset SO를 드래그하거나 ObjectField로 넣는다. 각 행의 숫자는 확률%가 아니라 상대 가중치다. 순서 이동/제거를 지원한다. 섹터 내부 배치는 Sector Maker에서 미리 작성한다.

새 Stage/복사/이름 변경/저장/Inspector/휴지통을 지원한다. 새/복사 Stage는 새 번호와 WIP 입장 차단을 사용하며, 실제 StageProgressionManager 입장 목록을 자동 변경하지 않는다. 복사는 하위 SO 참조를 유지하는 일반 에셋 복사다. 삭제는 확인 후 OS 휴지통으로 보내며 참조가 끊길 수 있음을 경고한다. Play/컴파일 중 원본 편집은 읽기 전용이다.

## 실제 생성기와의 일치

`StageMapBuildPipeline`으로 새 맵 생성과 SectorPreset 선택을 공통화했다. StageSectorInstantiator와 StageMakerPreview가 같은 함수를 사용한다. V3/구형 odd-square/Legacy 전체 격자/작성된 branch topology를 기존 정책에 따라 호출한다.

미리보기는 실제 퀘스트 런타임을 읽지 않는다. `필수 종류 시뮬레이션`에 `office,medical` 같은 ID를 입력하면 그 시드의 필수 조건만 모사한다. 런타임은 기존처럼 수락한 미완료 퀘스트를 읽는다. 시드뿐 아니라 이 조건까지 같아야 특별방 결과도 같다.

기존 코드의 역할별 프리팹 선택에 사용하던 지역 stageSeed는 새 runSeed를 추첨하기 전 값일 수 있었다. 이제 그래프에 저장된 layout.stageSeed로 통일해 지도/실제 배정이 일치하도록 했다.

저장된 원정 복원 경로에서는 공통 생성기를 다시 호출하지 않는다. 기존 특수방 ID와 새 전용/공용 분류(combatPoolId)는 방 노드에 저장한다. 저장된 분류/특수방이 현재 풀에서 사라졌다면 다른 맵으로 몰래 재추첨하지 않고 실패 이유를 낸다. 단, 일반 프리팹 선택 자체는 기존과 같이 현재 풀+저장된 시드 기반이므로, 진행 중에 풀 내용/가중치를 바꾸면 선택 프리팹까지 영구 고정되는 것은 아니다.

## 비율과 제한의 의미

### 현재 기본: 특별맵 비율 + 스테이지별 허용 종류

특별맵은 기본적으로 비율 모드(useRatio)를 사용한다. 비율의 단일 원본은 RoomComposition.specialPercent다.
전용/공용의 3분류 구성 토글이 OFF여도 특별맵 비율은 동작하며 나머지는 기존 일반 풀을 사용한다.
비율 예산에서는 해치/시작·발전실·보스·상인·탈출 후보 등 예약된 방을 제외한다.
기본은 허용 종류당 1개이며 종류 또는 배치 가능한 방이 부족하면 그 몫은 일반방으로 둔다.
허용 종류가 하나도 없어도 기본 비율 모드에서는 실패하지 않는다. 반복을 켜면 종류별 기존 최대 1 설정에 막히지 않고 비율 목표까지 추첨한다.

이전 최소/최대 값은 useAdvancedCountLimits를 켜야 비율 모드에 강제 적용한다.
퀘스트/미리보기의 명시적 필수 종류는 비율이 0이어도 최소 1개를 보장한다.
명시적 필수 종류가 OFF/미등록이거나 필수 위치/강제 최소를 만족할 수 없으면 오류를 유지한다.
일반 선택의 방향/거리 조건만 만족하지 못하면 해당 선택은 생략하고 일반방으로 채운다.
useRatio OFF는 이전 개수 방식이며 기존의 엄격한 최소/최대 의미를 유지한다.

Stage1은 특별 30%, 전용 비율 OFF, 사무실·창고 ON, 나머지 4종 OFF다.
Stage2~6은 이번 패치에서 바꾸지 않았다. 각 스테이지에서 등장 체크를 늘려 콘텐츠를 순차 개방한다.
빈 목록은 '기존 특별맵 등록 · 빠진 종류만' 버튼으로 기존 6종 프리셋을 연결할 수 있다.
새로 등록한 종류는 체크 OFF이며 기존 항목/ID/변형을 덮어쓰지 않는다.
미리보기에는 비율 목표·실제 특별맵·일반 대체 수량을 함께 표시한다.
새 레이드 생성에 적용하며 저장된 종류/변형 ID 해석 및 이어하기는 재추첨하지 않는다.

### 이전 개수 방식 / 3분류 호환 규칙

구성 ON 시 시작/해치·보스 역할·상인은 비율 대상에서 제외한다. 발전실/기존 금고는 특별 몫에 포함한다. 특별 목표에서 이미 예약된 발전실/금고를 뺀 개수를 추가 특별 종류 풀에 요청한다. 종류 풀의 최소/최대/퀘스트 필수 조건이 목표 비율보다 우선한다. 남는 몫은 공용 전투방으로 채운다.

특별 종류 풀의 최소/최대는 별도 발전실/기존 금고까지 포함한 총수 상한이 아니다. 기존 금고 알고리즘과 새 잠금보관실 종류를 함께 쓴다면 각각의 설정을 확인해야 한다. 금고를 작은 중앙 잠금구역+남쪽 패널1개+외곽 전투로 바꾸는 별도 콘텐츠/잠금 모드 패치는 이 작업에 포함하지 않았다.

거리/방향을 설정한 특별방은 후보 방과 추첨된 종류 사이의 매칭으로 배정한다. 제한 없는 종류가 북쪽 전용 종류의 유일한 후보를 먼저 차지하는 식의 단순 순서 문제를 피한다. 모든 조건을 동시에 만족할 수 없다면 실패 원인을 표시하며, 필수 조건을 몰래 완화하지 않는다.

V3의 중앙 해치1·발전실1·보스 후보1과 연결된 안전한 포탈 그래프는 현재 진행/저장 검증의 불변 조건이다. 이 개수를 임의로0으로 만드는 옵션은 넣지 않았다. 새 토폴로지 종류나 직사각 격자는 별도 알고리즘 확장이 필요하다.

## 검증

- 수정/추가 C#13파일의 C#9 구문 파싱: 오류0. 컴파일/타입 검사와 다르다.
- 대상 diff 공백 확인 및 새 스크립트 메타 GUID/필드/호출 연결 정적 점검.
- StageMakerTests 회귀 테스트 소스13사례 추가: 제안 크기4종/연결, 기본 고급규칙 호환, 거리 실패 이유, 미리보기-실행 동일성/비변경, 반복/종류 OFF, 필수 종류/방향, 변형 회피, 방향 조건 동시 매칭, 분류 저장·복원, 프리팹 선택 일치.
- Unity 컴파일·EditMode 테스트·Play Mode·실제 창 렌더링은 실행하지 않았다. 강제 AssetDatabase.Refresh도 호출하지 않았다.
- 읽은 Editor.log에는 VSplatter 참조 누락과 새 Stage 관련 타입 미인식 기록이 있었다. 자동 임포트/프로젝트 갱신 상태 또는 별도 컴파일 환경 문제를 이 작업에서 확정·수정하지 않았다. 따라서 전체 Unity 컴파일 성공이나 실제 창 실행을 확인한 것으로 보지 않는다.

다음 검증은 Unity의 프로젝트/어셈블리 갱신 상태를 확인한 뒤 StageMakerTests와 기존 Raid 회귀 테스트를 실행하고, 실제 창에서 우클릭 캡처·확대 중심·레이아웃·선택/표시를 확인하는 것이다.

## 생성 실패 안내 / UI 재정리 검증

### 1~7칸 소형 테스트 지원

격자 입력은 1~64칸이다. V3에서 1~7칸은 저장 가능한 compactTestLayout으로 생성한다.
1×1은 중앙의 일반방 하나가 HOME 탈출용 빈 방향 포탈을 소유하며, 발전실/보스/해치는 겹쳐 만들지 않는다.
2~7칸은 연결 우선 랜덤 방식으로 최소 4방을 만들고 발전실·보스 후보·해치·최소 1탈출을 서로 다른 방에 배정한다.
이 구간은 링과 별도 추가 금고 추첨을 생략한다. 후보 수/경로 거리/탈출구 수는 공간에 맞춰 조정하되 SO 값은 변경하지 않는다.
고급 목표/최대 방 수도 최소 4방과 격자 수용량 안에서 적용한다.
특별맵/전용맵 풀은 공통 파이프라인으로 이어지며, 퀘스트 필수/강제 최소 같은 명시적 불가능 조건은 그대로 오류를 낸다.
미리보기는 소형 테스트 여부와 실제 후보/탈출 수·최소 후보 거리를 표시한다.
8칸 이상은 원래 생성 경로와 엄격한 링/필수방 검증을 유지한다. compact 플래그로 큰 맵의 검증을 우회할 수 없다.

1~7칸, 3개 밀도, 16시드의 연결/격자 경계/저장 왕복/설정 및 Random 비변경 회귀 테스트 소스를 추가했다.
1×1의 실제 탈출 메타데이터와 잘못된 플래그/연결 거부도 검사한다. Unity 실행 결과는 별도 확인 대상이다.

`Tools/Checks/VerifyCompactRaidCore.ps1`을 별도 실행했다. 실제 생성기/검증기/포탈 정책 소스와 순수 타입·수학 대체 구현으로
1~7칸 × 3밀도 × 64시드 = 1,344개, 기존 크기 8/10/12/14/16 × 32시드 = 160개를 통과했다.
이 검사는 Unity 실행/프로젝트 컴파일이 아니며, Unity 임포트·Unity 직렬화·EditMode·Play Mode 통과를 뜻하지 않는다.

원거리 후보 부족 오류는 생성 설정 맨 위에서 한글로 보여준다. 예: 8×8, 생성 방 20개, 최소 거리 4칸, 후보 4개 중 3개 배치. 원본 오류는 접어서 보관한다.
V3 후보는 발전실/보스에도 쓰이므로 단순히 후보 수를 3으로 낮추라는 안내는 하지 않는다.
`거리 완화안 찾기 · 변경 없음`은 일반 설정 클래스 사본과 현재 시드로 구조 생성만 검사하며 SO를 바꾸지 않는다.
결과의 `적용 후 재생성` 버튼을 직접 눌러야 최소 거리를 수정한다. SerializedObject 경로로 적용해 Undo를 유지하고, 전체 특별맵/콘텐츠 조건을 다시 검사한다. 다른 시드 성공 보장은 아니다.
UI 패치 자체는 Stage SO/프리팹/생성 알고리즘을 변경하지 않는다.

레이아웃 3해상도, 패널 숨김, 한글 오류 설명, 완화안 탐색의 SO/Random 비변경 회귀 테스트 소스를 추가했다. 실제 Unity 실행/테스트는 별도로 확인해야 한다.

## 최신 변경: 거리 후보 폐기 / 가지 끝 발전실·탈출구 / 전용맵 보스

방 수 상한 때문에 필수 말단 수를 확보할 수 없으면 필요/확보 수와 조정할 설정을 명확히 표시한다.
1×1 일반방+HOME 탈출은 유지한다. 2~7칸은 역할 중복 없이 들어가는 실제 탈출 수로 축소하고 SO 입력값은 바꾸지 않는다.
상인 및 기존 추가 금고의 전역 시작 거리/후보 거리 제한은 없다. 특별 종류의 명시적 방향/거리/퀘스트 제약은 별도 사용자 설정으로 유지한다.

보스는 발전실/탈출 후보에 포함하지 않는다. 나머지 일반 구역 좌표에서 랜덤 선택한 뒤 해당 스테이지 전용 Normal 맵 풀에서 프리팹을 뽑는다.
Encounter와 가중치는 기존 보스 목록에서 사용하지만 전용 Boss Sector 쌍은 새 맵에 요구하지 않는다.

특히 아직 전용맵을 작성하지 않은 스테이지는 보스를 사용하기 전에 해당 풀 등록이 필요하다. 이번 변경은 Stage SO/프리팹을 임의로 채우거나 수정하지 않는다.
Stage Maker 미리보기와 실제 생성, Content Preflight에 같은 규칙을 연결했다.

기존 저장은 landmarkPlacementVersion=0으로 이전 후보/보스맵 쌍 해석을 유지한다. 로드 시 새 방식으로 재배치/재추첨하지 않는다.
새 규칙은 Stage Maker의 다시 생성 및 새 레이드에 적용된다.

검증은 실제 생성기 소스를 사용한 독립 관리 코드 검사와 C#9 구문 파싱이다. Unity 컴파일·임포트·EditMode·Play Mode는 실행하지 않았다.
회귀 테스트 소스에는 말단 유지, 보스 후보 분리/전용맵·Encounter 해석, 폐기 필드 무영향, 구버전 저장 복원 검사를 추가/갱신했다.
독립 코어 실행: 소형 1,344건 + 일반 160건 + 경계/말단/폐기 설정 검사 454건 = 총 1,958건 통과. 최대 64칸도 포함한다.

## 보스가 외곽 탈출 경로 막지 않기 옵션

Stage Maker > 1. 맵 크기·생성 규칙 > 탈출·발전실·보스에 체크를 추가했다. 기본 ON.
V3 신규 생성에서 실제 보스방을 제외한 그래프로 시작점부터 모든 외곽 탈출구까지 연결되는지 검사한다.
보스가 탈출구와 붙어 있는지나 최단 경로에 있는지가 아니라, 보스를 거치지 않는 다른 경로가 존재하는지가 기준이다.
보스가 샛길/막다른 방에 있거나 우회로가 있는 것은 허용한다. OFF는 기존 랜덤 보스 위치 규칙이다.
보스 확률 추첨은 ON/OFF에 영향받지 않으며 스테이지 전용맵 추첨은 유지한다.

원래 위치가 탈출 길목이면 안전한 다른 좌표로 보스를 옮긴다. 아주 작은 맵에서 필요하면 발전실/탈출 말단의 역할을 서로 바꾸어 보스 없는 탈출 경로를 확보한다.
그래도 가능한 배치가 없으면 명확한 오류를 낸다. 보스나 탈출구를 몰래 빼거나 연결을 새로 뚫지 않는다.
발전실 접근 및 해치 전원 경로까지 보장하는 옵션은 아니다. 기존 전투 중 포탈 잠금/해치 활성화/탈출 조건 자체를 변경하지 않는다.

선택은 StageMapLayout.bossAvoidsExtractionRoutes에 저장되며 실제 보스가 있는 보호 맵은 저장 검증에서도 우회 경로를 확인한다.
필드가 없는 과거 저장은 false로 해석하고 재배치/재추첨하지 않는다. SO 옵션 변경도 진행 중 저장 맵에 소급하지 않는다.

독립 코어 실행에 ON/OFF 672쌍을 추가: ON 안전 맵 654개, 공간 부족 소형 맵의 명시적 실패 18개.
OFF에서 실제 보스가 탈출을 막는 맵 293개를 확인했고 보호 스냅샷 ON으로 바꾸면 검증이 거부하는지 확인했다.
기존 1,958건 코어 검사도 통과했다. Unity 컴파일/직렬화/EditMode/Play Mode는 실행하지 않았다.

## 상인: 스테이지당 10% / 공용 전투맵 추가 등장

기존 '상인 방 1개' 선예약/클리어 방 생성 방식을 새 V3 생성에서 제거했다.
Stage Maker의 '2. 등장할 맵·특별방·상인'에 등장 확률, 상점 SO, 자금과 UI 채널 설정을 모았다.
merchantSpawnPercent 기본값은 10이며 스테이지 전체 1회 추첨이다. 방 수가 많다고 등장 확률이 증가하지 않는다.
0은 미등장, 100은 배치 대상 공용방이 있으면 확정. 성공 시 최대 한 곳만 선택한다.
별도 상인 맵 풀은 사용하지 않는다. 기존 merchantRoomCount는 호환 필드만 남기며 새 V3 생성/검증에는 사용하지 않는다.

추첨은 특별맵·전용/공용 비율 배정 후 실행한다. 공용 Normal 방 중 시작/해치·발전실·보스·금고·특별맵·탈출구·내부잠금 구역을 제외한다.
비율 모드 OFF의 일반방도 공용 후보이며, 선택되면 공용 풀(비었으면 기존 Normal 풀)에서 실제 맵을 해석한다.
상인은 room.hasMerchant 추가 표식이다. raidRole/방 종류를 Merchant로 바꾸거나 방을 클리어 처리하지 않는다. 기존 공용 전투/루팅/클리어 조건을 유지한다.
기존 SectorShop 규칙에 따라 해당 방을 클리어한 뒤 거래할 수 있다. 전투 중 즉시 거래 허용으로 변경하지 않는다.
기존 런타임 상점 팩토리와 UI를 재사용한다. 상인 외형/사전 배치 콘텐츠는 이 변경에서 새로 만들지 않았다.

상인 추첨 결과와 위치는 layout.merchantPlacementVersion/merchantRollSucceeded 및 room.hasMerchant로 저장한다.
진행 중 저장에 새 확률을 소급하거나 다시 추첨하지 않는다. 예전 Merchant 역할 방의 상점/클리어 상태는 그대로 유지한다.
후보 공용방이 없으면 특별맵/보스방을 빼앗지 않고 미등장하며, 미리보기에 '추첨 성공·공용 전투방 없음'을 구분 표시한다.
선택된 방은 '공용 전투·상인' 초록 표식이다. 게임 지도는 발견한 뒤 기존 상인 표식을 사용하고 전투방 정체성은 바꾸지 않는다.
상점 설정 누락은 설정 경고/미리보기 참조 오류/런타임 콘솔로 안내하며 조용히 생략하지 않는다.

독립 코어 검증: 10,000 스테이지 중 1,002개(10.02%) 등장. 후보 공용방을 2개에서 24개로 늘려도 같은 스테이지의 추첨 성공 여부가 같음을 확인했다.
0/100%, 후보 없음, 제외 구역, 최대 1명, 클리어 상태 유지, 저장 결정 재추첨 방지 및 실제 생성 그래프 32개 검증도 통과했다.
기존 소형/일반/보스 우회 검사도 통과했다. Unity 컴파일/임포트/EditMode/Play Mode/실제 UI 렌더링은 실행하지 않았다.

## 지도 이미지 편집 / 미니맵 이미지 미리보기

SectorPresetSO에 선택형 MapIcon(Sprite)을 추가했다. 기존 값은 비어 있으므로 기존 아이콘을 유지한다.
Stage Maker의 각 후보 맵 행과 미리보기에서 선택한 방 상세에 '맵 지도 이미지' 필드를 제공한다.
편집은 해당 SectorPreset 원본 SO에 적용되므로 같은 프리셋을 참조하는 스테이지에 공통 적용된다. 프리팹 배치나 맵 구조를 자동 수정하지 않는다.
'2. 등장할 맵'의 접힌 지도 이미지 설정에서는 미니맵/전체맵의 공통 해치·발전실·탈출·상인·보스·의료·보안·금고·잠금 아이콘도 함께 편집한다.
설정 SO가 하나일 때만 자동 선택하며 여러 개이면 실제 UI에서 사용하는 SO를 직접 지정하도록 안내한다.
현재 프로젝트의 MiniMapRoot/FullMapRoot가 각각 기존 MiniMapUISettings/FullMapUISettings 에셋을 참조하는 것을 정적으로 확인했다.

Sprite 편집은 SerializedObject의 Undo를 사용하며 상단 저장 버튼은 현재 Stage와 이 창에서 이미지 편집한 SO만 저장한다.
이미지 수정 자체로 생성 시드를 바꾸거나 맵을 재추첨하지 않는다. Stage Maker 미리보기는 원본 Sprite를 매번 읽어 교체를 반영한다.
미니맵 이미지 표시 토글은 기본 ON이며 편집용 전체 발견 상태로 보여준다. 기존 좌표·맵 설명·노란 탈출 배지는 유지한다.

런타임은 선택한 프리셋 이미지 -> SectorRuntime -> 공유 지도 스냅샷으로 전달한다. MiniMap/FullMap/Stage Maker가 같은 커스텀 이미지 우선 규칙을 사용한다.
발견한 일반/특별 맵에는 개별 이미지를 쓰며 탈출·보스·상인은 공통 중요 표식이 있을 때 그 표식을 유지한다.
미발견/잠긴 방에는 커스텀 이미지를 표시하지 않는다. 기존 공개 발전실·해치 등의 표식만 유지하며 실제 플레이의 발견 규칙을 바꾸지 않는다.
Sprite 비율을 유지하고 편집기에서 슬라이스/패킹 이미지도 텍스처 전체 대신 해당 Sprite로 미리본다.

독립 실제 소스 아이콘 정책 검사와 Unity용 회귀 테스트 소스를 추가했다. Unity 컴파일/직렬화/Undo/실제 창 렌더링/Play Mode 검증은 별도로 필요하다.

## 정정: 개별 맵 이미지가 아니라 종류별 공통 Sprite

위 '개별 SectorPreset MapIcon 편집' 설명은 사용자의 의도와 달라 폐기한다.
왼쪽 목록 최상단에 '지도 Sprite·전체 공통' 메뉴를 추가했다. 이 페이지는 Stage 선택과 독립이며, 종류별 큰 썸네일과 Sprite 교체 칸을 한 화면에 표시한다.
오른쪽 방 상세/후보 맵 목록의 개별 이미지 편집기는 제거했다. 우측은 테스트 지도와 읽기 전용 방 정보만 유지한다.

새 공통 SectorMapIconSetSO(SectorMapIcons.asset)에 일반 공용 전투, 스테이지 전용 전투, 보스, 금고, 사무실, 창고, 보안실, 의료실, 서버실, 발전실, 해치, 외곽 탈출, 상인, 미발견, 네임드의 15종 Sprite를 모았다.
기존 MiniMapUISettings와 FullMapUISettings에 같은 공통 SO 참조를 연결했다. 기존 프로필 값은 삭제하지 않고 연결 해제 시의 구버전 호환용으로 유지한다.
처음 이미지는 기존 전체맵에 이미 쓰던 Sprite 참조를 옮겼으며 임의의 새 그림을 만들지 않았다. 새 종류 일부는 일반 전투 이미지를 기본으로 따른다.
공통 SO가 연결돼 있으면 종류별 값이 양쪽 지도에 동일 적용된다. 일반/보스/금고 등의 칸을 비우면 이미지가 사라지며 이전 두 프로필의 서로 다른 이미지가 되살아나지 않는다.
스테이지 전용·사무실·창고·서버실 칸을 비우면 일반 전투 Sprite를 따른다.

실제 생성 노드의 역할·특별 풀 ID·전용/공용 분류로 지도 종류를 결정해서 SectorRuntime과 스냅샷에 전달한다. 보스가 미출현한 예약 일반방은 보스 이미지로 표시하지 않는다.
미발견/잠금 상태는 공개 표식 외 실제 종류 Sprite를 숨기는 기존 규칙을 유지한다. 미리보기는 종류별 공통 SO와 같은 렌더 선택 정책을 사용한다.
앞 패치의 개별 프리셋 Sprite 필드는 혹시 저장된 참조를 지우지 않도록 숨긴 WIP 데이터로만 남겼고 표시 계산에서는 사용하지 않는다.

저장은 현재 공통 SO 및 이 창에서 변경한 지도 연결 SO만 대상으로 하며 Stage/프리팹/배치/생성 시드는 바꾸지 않는다. Undo는 SerializedObject 경로를 사용한다.
독립 실제 소스 정책 검사 499개와 양쪽 SO 연결 및 편집기 15개 필드명을 정적으로 검사했다. Unity 임포트/컴파일/실제 창/Undo/Play Mode 검증은 수행하지 않았다.

## 외곽 탈출구와 방 종류 Sprite 동시 표시

Stage Maker 미리보기와 인게임 미니맵에서 외곽 탈출구는 방 종류 Sprite를 덮어쓰지 않는다. 왼쪽에 원래 방 종류(공용/전용/특별 등), 오른쪽에 외곽 탈출구 Sprite를 나란히 표시한다. 외곽 탈출 역할을 가진 노드도 바탕 전투 종류를 별도로 전달한다.
미발견/잠긴 방의 실제 종류는 계속 숨긴다. 공개된 탈출구만 있는 미발견 방은 미발견 Sprite + 탈출구를 표시한다. 해치/시작방의 탈출 상태는 이 외곽 표식 중복 대상이 아니다. 이미지 한쪽이 비어 있으면 남은 이미지 하나만 중앙에 표시한다.
MiniMapCell 프리팹에 두 Image를 미리 배치·연결했다. 원래 Image 및 자식 텍스트의 RectTransform은 변경하지 않고, 셀 재사용/잠금/누락 처리 시 두 이미지를 초기화한다. 미연결된 구버전 셀 변형은 최소한 탈출구 표식 하나를 유지한다. 전체맵은 이번 두 화면 요청 범위에 포함하지 않았다.
실제 소스 표시 정책 575개와 프리팹 Image 참조/중복 fileID를 독립 검사한다. Unity용 두 이미지/셀 재사용 회귀 테스트 소스도 추가했으나 Unity 임포트/실제 UI 렌더링/Play Mode 검증은 수행하지 않았다.
