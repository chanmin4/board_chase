# Board Chase 레이드 패치 결과 · 2026-09-18

## 결론

P00~P11의 코드와 초기 데이터 연결을 적용했다. P09/P10은 요청대로 **비활성 기획/작성용 WIP 데이터**만 만들었다.
P12는 읽기 전용 검증이며, 이 단계에서 찾은 문제는 패치하지 않았다.
**전체 게임 실플레이 완료 판정은 아니다. 루팅-퀘스트 저장 시점 문제 1건을 재현했으며 다음 패치 우선 대상이다.**

## 적용한 규칙

| 항목 | 적용 |
|---|---|
| 스테이지 크기 | 7×7 / 9×9 / 11×11 / 13×13 / 13×13 |
| 시작 | 외부 허브 (-1,0) 유지. 실제 귀환 단말기 제공. 첫 그리드 방 (0,0) |
| 중앙 해치 | (N/2,N/2), 정수 0-based 좌표. 발전소 전력 전에는 탈출 불가/마커 비공개 |

| 보스·일반 탈출 | 우상단의 서로 다른 두 칸. 보스는 생성 시 65% 한 번 결정 |
| 보스 미등장 | 후보 위치는 예약하되 일반 전투 방으로 사용. 보스 마커 없음 |
| 초기 공개 | 시작 귀환/일반 탈출/발전소/실제 등장 보스. 주변 점유 정보는 공개하지 않음 |

| 전체 시간 | 연결 검증용 1,200초. Time.deltaTime 기준, timeScale 일시정지 및 오프라인 동안 경과 없음 |
| 전체 시간 초과 | 기존 방 가스 노출/가스마스크 경로에 초당 6을 더함. 별도 피해 Update를 만들지 않음 |
| 특별 탈출 | 해치와 별개. Stage3+ 설정/종류만 있는 비활성 WIP. 실제 위치·조건·보상 없음 |
| 방 콘텐츠 | 의무실 의료품 / 무기고 총·탄약 및 Armed 특성 / 금고 Valuable·자금 |
| 방탄 | 실드 → 방탄복 → 기본 방탄을 독립 계산. 각 레이어의 실제 흡수량만 그 레이어 내구도에 반영 |
| 고정 근접 | 기존 5 피해/방탄 무시 계약 유지. 실드 내구도도 깎지 않음. 회피·무적은 유지 |
| 정렬 | 플레이어 포켓/가방 각각 위로 모으기·등급순. 스택을 병합하지 않고 객체와 내구도를 그대로 이동 |

20분, 가스 6, 방 비율 Normal70/Armory10/Medical15/Vault5, 배터리 1개, 탈출 최소거리 N은
**초기 연결 값**이다. 확정 밸런스가 아니고 P12에서 조정하지 않았다.
기존 적 탄약·보스 HP·방탄 내구도 수치는 이번 P12에서 일괄 변경하지 않았다.

## Unity에서 설정할 위치

- `Assets/ScriptableObject/GameScene/Stage/Stage1Definition.asset` ~ `Stage5Definition.asset`
  - Map Policy = OddSquareRaid. 레이드 설정과 seed 기반 배치 미리보기.
  - Raid Runtime: 시간, 가스, 배터리, 오디오, 단말기 프리팹, 역할별 방/전투/콘텐츠 override.
  - 역할 전용 방이 비어 있으면 기존 Normal 풀을 사용한다. 레거시 branch topology는 삭제하지 않고 정책 선택으로 보존했다.
  - 단말기 프리팹이 비어 있으면 기존 E 상호작용을 쓰는 임시 TMP 표시/트리거를 생성한다. NEXONLv1GothicRegular SDF 연결.
- `Assets/ScriptableObject/GameScene/Stage/RaidLoot/`
  - 의료품 12종, 무기/탄약 43종, Valuable/자금 36종의 초기 풀.
  - Armory 일반 풀에서 Lv7/8 탄약은 제외. 이는 전체 게임의 모든 상점/드롭 경로를 차단했다는 뜻은 아니다.
  - 기존 상자가 있으면 인스턴스의 풀만 교체하고, 없으면 기존 상자 프리팹을 임시 위치에 생성한다.
- `Assets/ScriptableObject/GameScene/Stage/RaidProgressionDraft_WIP.asset`
  - Normal Valuable10 → Boss1+금액 → Stage2; Rare/Unique/Legendary로 다음 스테이지 초안.
  - 상위 등급 수량/금액 0은 미정 값이지 공짜 완료 조건이 아니다.
  - 방탄 Lv2/3/4, Stage3 주사기, 탄약, 스탯, 창고 초안.
  - Shop1~6 / 특수 파밍7~8 정책 기록만 존재. 런타임 자동 해금/제한을 강제하지 않는다.
- 실더 보스는 나중에 해당 엔티티에 `ShieldArmorRuntime`을 붙여 방탄 클래스/내구도를 설정한다.
- `Tools > Board Chase > Save Inspector`에서 레이드 좌표·전력·시간·가스·보스 상태를 읽을 수 있다.

## 저장 범위와 한계

- run schema 1 → 2. 이전 플레이어 인벤토리/체력은 유지하고 구형 데이터에 임의의 맵을 만들지 않는다.
- seed뿐 아니라 확정 그래프, 보스 등장 결과, 방 공개/클리어, 현재 방, 발전소, 시간/가스를 보관한다.
- 바인딩된 LootableObject의 roll 여부, 남은 슬롯/수량/개별 내구도, 잠금 해제를 보관한다.
- 누락된 상자 아이템 GUID는 경고 후 그 아이템만 제외하며 빈 상자를 재추첨하지 않는다.
- 자동 run 체크포인트는 게임 시간 10초 간격. 초기 입장/전력 거래 및 기존 종료 저장 경로와 연결.
- 현재 방 안의 정확한 적 HP/위치/전투 도중 상태, 시체와 바닥 아이템 전체, 개별 방 타이머/가스 누적은 새 월드 스냅샷 대상이 아니다.
  미클리어 방 재접속은 전투가 재구성될 수 있다. **완전한 전투 중단점 복원으로 홍보하면 안 된다.**
- 실제 전원 차단을 포함한 기존 temp/backup 교체 경로의 장애 주입 검사는 이번에 다시 실행하지 않았다.

## P12 발견 사항 — 요청에 따라 수정하지 않음

### 높음: 루팅 도중 퀘스트 저장이 중간 상태를 잡을 수 있음

재현 결과:

```
Transferred=True
duplicate snapshot visible during OnChanged=True
final container items=0
```

`EnemyLootInventoryRuntime.TryTakeItemStack`은 플레이어 인벤토리에 추가하고 OnChanged가 발생한 **뒤에** 원본 stack.Clear()를 수행한다.
`QuestRuntime.HandlePlayerInventoryChanged → RefreshCollectObjectives → NotifyStateChanged → PersistStates`는
수집 진행이 변하면 같은 콜백 안에서 SaveDataToDisk를 호출할 수 있다.
이때 새 상자 스냅샷까지 저장하면 플레이어와 상자 양쪽에 같은 물건이 포함된 중간 상태를 잡을 수 있다.
다음 정상 체크포인트 이전에 종료/크래시하면 복제 가능한 저장으로 이어질 위험이다.

격리 Unity에서 **OnChanged 중 양쪽 소유가 동시에 보이는 상태를 재현**했다.
퀘스트와 실제 사용자 세이브 파일 전체를 결합한 크래시 재현까지 실행한 것은 아니다.
후속 수정 방향: 루팅 거래가 끝난 뒤 저장하도록 거래 경계를 두거나, 원본 제거/롤백과 알림 순서를 원자적으로 묶기.
해당 프로덕션 코드는 P12에서 변경하지 않았다.
추가 검증 원시 결과: `Temp/RaidValidation/loot-save-window.txt`, `audit-probe.log`.

### 남은 실제 플레이 검증

1. Stage1 7×7에서 시작 허브 귀환 → 재입장 → 일반 탈출 → Home 인벤토리/정산.
2. BatterySmall 소지/미소지, 연타, 발전소 가동 후 해치 표시 및 E 탈출.
3. 실제 프리팹에서 단말기/상자 위치가 벽·장애물에 묻히지 않는지.
4. Stage3 기본 가스 + 레이드 시간 초과 가스 + 가스마스크 필터 소모.
5. 전투 중 강제 종료/재실행 시 허용할 월드 복원 정책 확정.
6. 13×13 생성/NavMesh/활성 AI 수/메모리/맵 UI 성능 계측.
7. 새 정렬 버튼, 지도 라벨, TMP 한글 및 실제 AudioCue 재생 확인.

기존 `ProjectSettings/EditorBuildSettings.asset`의 씬은 여전히 모두 enabled:0이다.
독립 실행 빌드/Boot 검증의 선행 이슈이며 이번 P12에서는 설정을 변경하지 않았다.
