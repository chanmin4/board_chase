# 레이드 네 모서리 시작 패치 · 2026-09-22

## 적용 범위

새 OddSquareRaid는 네 모서리 중 한 곳으로 진입한다. 기존의 외부 시작 허브, 시작 귀환 단말기, Home 귀환 흐름은 유지한다. 중앙 시작이나 스테이지 간 이동/연속 퀘스트는 구현하지 않는다.

| 첫 입장 모서리 | 보스·일반 탈출구 후보 영역 | 발전소 후보 영역 |
|---|---|---|
| 왼쪽 아래 | 오른쪽 위 | 왼쪽 위 또는 오른쪽 아래 |
| 오른쪽 아래 | 왼쪽 위 | 왼쪽 아래 또는 오른쪽 위 |
| 오른쪽 위 | 왼쪽 아래 | 왼쪽 위 또는 오른쪽 아래 |
| 왼쪽 위 | 오른쪽 아래 | 왼쪽 아래 또는 오른쪽 위 |

- 홀수 N×N과 중앙 해치 유지. m=N/2 정수 나눗셈. 각 모서리 m×m 영역에서 중앙 행·열은 제외한다.
- 보스와 일반 탈출구는 반대편 영역의 서로 다른 칸이다. 기존 보스 확률 65%, 미등장 시 보스 자리 예약 정책 유지.
- 발전소는 나머지 두 모서리 영역 중 하나에 하나만 배치한다.
- 최소 탈출 경로 거리는 실제 시작 허브부터 계산한다. 회전은 거리와 도달성을 바꾸지 않는다.
- 배터리/해치 공개/가스/레이드 시간/루팅/Home 정산/특별 탈출 WIP는 변경하지 않았다.

## 좌표와 구현

`RaidMapGenerator`는 기존 왼쪽 아래 기준 배치를 생성한 뒤 중심을 기준으로 0/90/180/270도 회전한다. 좌표와 Left/Right/Down/Up 연결 플래그를 함께 회전한다. 방 프리팹의 아트나 Transform을 회전하는 방식은 아니다. 기존 네 방향 포털이 새 연결 플래그에 따라 연결된다.

방향 추첨은 stage seed를 별도로 섞어 기존 발전소 방향 추첨과 상관되지 않도록 했다. 같은 run seed/stage/settings면 동일한 결과가 나온다. 고정 seed 디버그 모드에서는 매번 같은 모서리가 나오는 것이 정상이다.

현재 RUNScene의 기본 외부 허브 입력 `(-1,0)` 기준 실제 좌표는 다음과 같다. 좌표는 0-based, +Y가 지도 위쪽이다.

| 첫 입장 방 | 외부 시작 허브 |
|---|---|
| (0,0) | (-1,0) |
| (N-1,0) | (N-1,-1) |
| (N-1,N-1) | (N,N-1) |
| (0,N-1) | (0,N) |

`StageSectorInstantiator`는 작성용 기본 좌표가 아니라 확정된 `CurrentLayout.startSectorCoord`로 시작 방을 판정한다. 기존 `SectorStateManager`, `SectorPortalManager`, 입장 위치/지도 공개 경로는 이미 layout 좌표 기반이어서 연결 구조를 유지한다.

## 저장 및 작성 화면

- 맵 생성 버전만 1 → 2. run 파일 schemaVersion은 기존 2 유지.
- 저장된 V1 레이드는 왼쪽 아래 시작과 원래 지도/플레이어 위치/전력 상태를 그대로 읽는다. 불러오기 시 회전하거나 seed로 재생성하지 않는다.
- V2는 확정된 네 모서리 지도와 현재 위치를 그대로 저장/복원한다.
- 알 수 없는 생성 버전 또는 잘못된 영역/진입점/그래프는 저장 검증에서 거부한다.
- Legacy/branch topology 생성은 변경하지 않았다.
- Stage1~5 Definition Inspector의 Preview seed를 변경하면 실제 시작 모서리를 확인할 수 있다. `S`=외부 시작 귀환 허브, `P`=첫 입장 방. 외부 허브까지 미리보기 범위에 포함한다.
- 기존 레이드를 이어 하면 기존 시작점이 유지된다. 네 모서리 패치를 확인하려면 Home에서 새 레이드로 입장한다. 사용자 세이브를 지울 필요는 없다.

## 검증

실제 사용자 씬을 열거나 저장하거나 플레이 세션을 종료하지 않고, 별도 임시 Unity 프로젝트에서 검사했다.

- 수정한 런타임/에디터와 테스트 소스 컴파일.
- Stage1~5 각각 1,000 seed: 영역, 중복, 전체 도달성, 네 방향 연결, 시작 허브 단일 연결, 실제 설정의 최소 탈출 거리, 모서리 분포.
- 보스 0/65/100%, 결정론, 콘텐츠 가중치와 위치 추첨 분리.
- 네 모서리 저장 왕복과 시작 귀환 조건, V1 보존, 알 수 없는 버전 거부.
- 네 모서리의 실제 SectorStateManager/SectorPortalManager 컴포넌트 연결과 첫 방 클리어 후 허브 복귀.
- 실제 ES3 파일 왕복, 초기 지도 마커/해치 숨김 회귀.

최종 결과: **34개 통과, 실패 0**. 위 5,000개 맵 검사는 5개의 스테이지별 테스트에 포함된다.

- 프로젝트의 현재 Unity 6000.0.47f1 컴파일 응답 파일을 사용한 런타임 컴파일: 오류 0, 기존 경고 15.
- 수정한 테스트를 포함한 전체 Assembly-CSharp-Editor 컴파일: 오류 0.
- 격리 Unity 엔진에서 NUnit 테스트 메서드 34개 실행: 34/34 통과. 원본과 같은 소스를 별도 이름의 검사 DLL로 컴파일하여 기본 Unity 어셈블리 이름 충돌을 피했다.
- 원시 결과: `Temp/RaidCornerValidation/results.txt`, `Temp/RaidCornerValidation/unity-complete.log`.
- 최초 검사에서 작은 XOR salt 간 상관으로 발전소 위치가 치우치는 것을 발견했다. 모서리 추첨 seed를 별도로 충분히 섞은 후 분포 검사를 포함해 재실행하여 통과했다.
- 변경한 7개 C# 파일을 작업 전 사본과 비교한 whitespace 검사도 통과했다. 기존 대규모 미추적/리팩터링 작업은 유지했다.

원본 프로젝트의 아트/카메라/충돌/전체 Home 정산 실플레이와 독립 실행 빌드 완료를 의미하지 않는다.
