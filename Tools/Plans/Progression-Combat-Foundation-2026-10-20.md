# 진행·패시브·전투 연결 토대 — 2026-10-20

## 작업 경계

사용자가 지정한 1~5번 시스템과 제작/디버그 도구 연결을 소스에 반영했다. 기존 미커밋 작업을 보존했다. 요청에 따라 빌드, Unity 컴파일/Refresh, 자동 테스트, Play 실행은 하지 않았다. 아래는 동작 검증 완료 보고가 아니다. 노션은 이번 작업에서 수정하지 않았다.

## 1. 해치의 원정 내 스테이지 전환

- StageDefinition의 Raid Runtime에 `hatchAdvancesStage`(기본 ON)와 `hatchRequiredQuest` 추가. OFF이면 기존 HOME 해치 탈출을 유지한다. 일반 외곽 탈출은 변경하지 않는다.
- 실제 현재 해치 위치, 방 클리어, 발전기 전력, 선택 퀘스트 완료, 다음 스테이지 접근 해금과 입장 가능한 원정형 맵을 확인한다. 마지막/미등록 스테이지는 명확한 실패 이유로 거절한다.
- 현재 원정을 먼저 저장하고 생성 맵을 교체한다. 플레이어를 생성 방 계층에서 분리하고 기본 탄환을 정리한다. HOME 정산·완료 보상·새 해금은 호출하지 않는다.
- 기존 플레이어의 장비·패시브·체력·감염을 그대로 사용하고 억제제·앰플 남은 시간을 새 RaidRuntime에 전달한다. 새 층의 발전기/맵은 새로 생성한다.
- 새 맵 생성 실패 시 이전 원정 스냅샷 복구를 시도한다. 복구도 실패하면 이전 저장을 보존하고 로딩 실패를 표시한다. 다음 층의 프리셋·적/루팅·퀘스트 데이터는 별도 등록해야 한다.
- HOME 직통 출발 해금은 이번 1~5번 범위에 포함하지 않았다. 기존 StageUnlock과는 별도 정책/보상 연결이 필요하다.

## 2. 영구 패시브 장착칸 퀘스트 보상

- QuestRewardType에 PassiveSlots 추가. Quest Maker의 `+ 패시브칸`에서 지급량을 설정한다.
- 퀘스트 ID + 보상 인덱스를 영구 프로필에 기록하여 재지급을 방지한다. 기본 2칸, 현재 상한 5칸을 유지한다.
- 플레이어 생성·런 복원 시 영구 해금 수를 반영한다. 사망으로 런이 초기화되어도 프로필 해금은 유지한다. 실제 보상 퀘스트는 자동으로 만들지 않았다.

## 3. 개체별 랜덤 패시브

- Item Maker/공용 설정에서 `개체별 랜덤 스탯`을 ON하고 희귀도별 스탯·최소·최대 범위를 설정한다. 기본 OFF라 기존 고정 SO를 일괄 변경하지 않는다.
- 각 범위는 최종 절대 FlatAdd 값이다. 효과 종류는 작성한 행으로 고정하며 그 수치를 추첨한다. 효과 종류 자체의 무작위 선택은 이번 범위가 아니다.
- 생성된 패시브는 원본을 바꾸지 않는 런타임 복제 개체이며, 고유 ID·최종 희귀도·확정 스탯·기능 플래그를 프로필/런 파티션에 저장한다. 복원 시 현재 범위로 재추첨하지 않는다.
- 편집 모드의 루팅 미리보기는 개체를 생성하거나 프로필을 수정하지 않는다. 격리 전투 실험실의 추첨은 실제 프로필/런 기록에 추가하지 않는다.
- 공통 Item GUID 전달 경로와 RuntimeContentCatalog를 확장해 인벤토리·장착·상자/적 드롭·바닥·창고의 개체를 복원한다. 원본 SO는 런타임 카탈로그에 등록되어 있어야 한다.
- 루팅 수량은 개별 패시브 개체로 분리한다. 랜덤 패시브의 바닥 배치는 자리당 수량 1을 사용한다. 다량의 바닥 패시브는 별도 배치 슬롯으로 구성하며, 잘못된 다량 설정은 오류를 표시하고 생성을 거절한다.
- 중복 획득과 같은 종류 중복 장착을 분리했다. 여분 판매를 원하면 중복 획득을 허용한다. 같은 개체의 두 슬롯 장착은 금지한다.
- 특정 원본 SO 제출/교환은 해당 종류의 개체를 받는다. 정확한 개체를 요구하는 요청은 다른 개체와 혼동하지 않는다. 장착 중인 패시브는 자동 재료에서 제외한다.
- 교환 상품 지급 실패 시 소비했던 정확한 패시브 개체를 복원한다. 새 추첨으로 보상하지 않는다. 같은 희귀도 아무 패시브를 받는 범주 교환은 아직 별도 구현이다.
- 저장할 때 참조 중인 개체 기록만 유지하여 버려진 추첨 기록이 저장 파일에 계속 쌓이지 않게 한다.

## 4. 소수점 관통력

- 플레이어/적 스탯, 탄환 정의·발사 스냅샷·BasicBullet, Damageable, 방탄·실드·레이드/기존 피해 공식 및 근접/투척 공통 계약을 float로 연결했다.
- 플레이어/적의 관통 보너스 정수 반올림을 제거했다. 기존 수치와 필드명은 유지하며 대량 SO 수치 변경은 하지 않았다.
- Item Maker/Character & Status Maker에서 소수점을 입력하고 Debug Monitor/아이템 상세에서 확인할 수 있다. 관통 확률 공식 자체를 새 밸런스로 교체하지 않았다.

## 5. 헤드샷 퀘스트

- HeadshotHit/HeadshotKill 목표 추가. 최대 정조준 시 후보가 된 적에게 실제 HP 피해가 발생했을 때 보고한다.
- 처치 여부와 발사 당시 무기를 전달하여 도착 전에 무기를 교체해도 헤드샷 무기 조건을 바꾸지 않는다. 일반 Hit/Kill과 별도 목표라 같은 목표를 중복 보고하지 않는다.
- 기존 BasicBullet 계열 범위다. 폭발/별도 특수 투사체에 헤드샷을 자동 확대하지 않았다. 실제 목표/보상 데이터는 Quest Maker에서 작성한다.

## 도구 사용 위치

- `Tools → Gameplay → 진행·전투 공용 설정`: 해치/퀘스트 조건·특별 섹터 풀, 공통 이동/스태미나·반동·적 방탄 드롭, 패시브 범위, 파괴 연기·시야 테두리를 편집한다.
- Item Maker는 선택 아이템을 공용 설정으로 전달한다. Sector Maker 구조물 배치에는 공용 연기/특별 섹터 설정 진입점을 추가했다.
- Debug Monitor의 Stage & Start Hub에 공용 설정, 랜덤 패시브 1개 지급, 실제 해치 조건을 적용한 다음 스테이지 이동, 장착칸·특별 섹터 수·전환 메시지를 추가했다.
- 공용 설정의 `실시간` 탭에서는 선택한 플레이어/적의 스태미나를 개체별로 임시 수정한다. 원본 SO·저장에는 반영하지 않으며 해제 버튼으로 원본 설정으로 돌아간다.
- 원본 SO는 Play 중 읽기 전용이다. 편집 모드에서 대상 SO를 고른 뒤 원본 저장을 사용한다. 시야 표현은 씬 컴포넌트를 대상으로 한다.

## 아직 제작할 콘텐츠

새 스테이지/특별 섹터의 실제 프리셋·가중치·퀘스트 참조, 패시브별 희귀도 범위·가격·출현율·교환 요구표, 슬롯 보상/헤드샷 목표 퀘스트, 적별 달리기·방탄 수치와 엄폐 프리팹 지정은 자동 작성하지 않았다. 도구 연결과 완성 콘텐츠 등록을 구분한다.
