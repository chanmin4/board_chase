# Item Maker: 손 소켓 표시와 카테고리 드래그 이동

## 손에 표시하기

- 일반 Consumable / Medical은 `World Visual Prefab`만 지정하면 기존 총과 같은 손 소켓에 표시된다.
- 프리팹에 저장된 루트 위치·회전·크기는 그대로 유지한다. 보정값은 별도 부모 오브젝트에 적용된다.
- `Hand Position Offset`, `Hand Rotation Offset`, `Hand Scale Multiplier`는 이 부모의 추가 보정이다.
- 아이템마다 손 전용 모델이 필요한 경우에만 `Hand View Override`를 지정한다. 기존 WeaponView 참조와 절대 보정값은 호환성을 위해 그대로 유지한다.
- `Resolved Hand Visual`에서 실제 선택되는 모델을 확인할 수 있다.
- 손에 표시하는 월드 비주얼 복제본의 Collider/Rigidbody는 물리 충돌을 하지 않는다. 원본 프리팹은 변경하지 않는다.
- World Visual Prefab은 기존 ItemSO 규약대로 **순수 비주얼**이어야 한다. 전체 ItemPickup이나 상호작용 오브젝트를 지정하지 않는다.
- Throwable은 기존 전용 WeaponView + ThrowableProjectile을 그대로 사용한다. 일반 표시 모델을 실제 수류탄 발사체로 자동 대체하지 않는다.
- 총의 발사 위치, 의료품 사용 효과/소모 시점, 투척 로직은 바꾸지 않는다.

## 카테고리 이동

1. 가운데 아이템 카드를 클릭한다. `Ctrl+클릭`으로 추가 선택/해제하고, `Shift+클릭`으로 현재 목록의 연속 범위를 선택한다. 선택한 카드 중 하나를 잡아 왼쪽 카테고리로 드래그하면 전체가 이동한다. Project 창의 여러 ItemSO 드래그도 가능하다.
2. 여러 개 이동하거나 다른 SO 타입으로 변경되면 한 번의 확인창에서 이동/타입 변경/유지 개수와 이전 타입 전용 필드를 확인한다. 같은 타입·기본 폴더에 이미 있는 항목은 건너뛴다.
3. Weapons / Bullets / Keys처럼 구체 타입이 여러 개면 드롭 후 타입을 선택한다.
4. 이동 후 오른쪽 패널에서 새 타입의 효과·사용시간·발사체 등 설정을 검토한다. 예를 들어 Passive의 공격력 효과를 Medical의 치료 효과로 자동 해석하지 않는다.

같은 종류 안에서 이동하면 전문 하위 타입은 유지한다. 상위 Weapons / Bullets / Consumables에 드롭하면 이미 포함된 하위 항목은 변환하거나 이동하지 않는다. All Items는 필터라 이동 목적지가 아니다.

### 무기·탄약 하위 분류 (2026-09-18)

- Weapons: SMG, AR, LMG, Pistol / Revolver, Shotgun, Sniper Rifle, Special (Rocket etc.). 전용 근접무기는 기존 `WIP / Melee Weapons`에 따로 남는다.
- Bullets: Light (Pistol / SMG), Medium (AR), Heavy (LMG / Revolver), Shotgun Shells, Sniper Rounds, Special / Rockets.
- 파일 이름이나 폴더를 추측하지 않고 `RangedWeaponSO.WeaponType` / `BulletSO.Family`로 필터링한다. 기존 총 13개·탄약 41개는 데이터 변경 없이 자동으로 분류된다. 물리 폴더의 강제 일괄 이동은 하지 않는다.
- 하위 분류 버튼을 선택하면 생성 템플릿도 해당 종류로 맞춘다. 생성 시 실제 무기 타입을 초기화하고, 새 아이템이 현재 필터/검색 때문에 숨지 않도록 선택한다. Shotgun은 산탄 발사 동작이 있는 `ShotgunWeaponSO`로 생성한다.
- 하위 분류로 드래그하면 실제 SO 종류/무기 타입과 기본 폴더를 함께 변경한다. 예: SMG → AR은 `_weaponType` 및 호환 탄종(Light → Medium)이 바뀐다. 기존 피해량·연사력·탄창 수치를 자동으로 재밸런싱하지는 않는다.
- Pistol / Revolver에 이미 속한 리볼버를 같은 분류로 드롭해도 Pistol로 바꾸지 않는다. 기존 Basic/Light 탄약의 구체 클래스도 같은 분류에서는 보존한다.
- 같은 SO 클래스 내 무기 타입 변경도 확인·백업·복구에 포함된다. Shotgun → AR처럼 클래스가 달라지면 산탄 전용 값은 원본 백업에 남고, Restore Last Move 시 되돌아온다.
- 이 변경의 검증: 수정 Editor 코드 컴파일 오류 0. 생산 런타임 DLL과 실제 Editor 소스를 사용하는 격리된 Unity 6000.0.47f1 실행에서 `ItemMakerWeaponCategoryTests` 24개 + 기존 `ItemMakerBatchTests` 7개, 총 **31개 통과**. 분류·템플릿·무기 타입 변경·산탄/탄약 클래스 변환·GUID/튜닝 보존·복구·기존 다중 선택을 포함한다. 실제 창의 마우스 드래그 화면 검증은 별도다.

선택한 카드는 모두 강조 표시되며 검색줄에 선택 개수가 표시된다. 오른쪽 편집·삭제·이미지 작업은 현재 활성 아이템 **하나만** 대상으로 한다(다중 데이터 편집이 아님). 선택 묶음을 누른 채 드래그하면 묶음이 유지되고, 드래그 없이 일반 클릭을 마치면 한 개만 선택된다. 검색/카테고리를 바꿔 숨겨진 카드는 선택에서도 빠진다.

실제 `.asset`도 해당 카테고리의 기본 폴더로 이동한다. 이름 중복은 덮어쓰지 않고 이동을 중단한다. GUID / local fileID / 유효한 저장용 Item Guid와 공통 이름·번역 참조·아이콘·월드 모델·가격·스택을 보존한다. 생성 직후 아직 비어 있는 저장용 Guid는 기존 에셋 GUID로 초기화한다.

### 참조 보호와 복구

- ItemSO 기반 참조는 유지하고 이미 로드된 데이터/씬의 참조도 새 관리 객체로 갱신한다.
- WeaponSO / PassiveItemSO 등 특정 타입만 받을 수 있는 필드와 호환되지 않으면 이동을 막고 경로·필드명을 표시한다.
- 아이템을 직접 참조하는 닫힌 씬은 자동으로 열지 않는다. 해당 씬을 먼저 열어 검증하도록 안내한다.
- 열려 있는 참조 소유자에는 갱신이 반영되지만 다른 에셋/씬을 일괄 저장하지 않는다. 필요한 경우 Unity의 일반 저장 흐름으로 저장한다.
- Play Mode, 컴파일 중, 읽기 전용 에셋, 서브에셋은 이동하지 않는다.
- 원본 `.asset`과 `.meta`, 이동 기록은 프로젝트의 `UserSettings/ItemMakerMoveBackups`에 남는다.
- 일괄 이동은 모든 선택 항목의 이름 중복/중복 목적지/타입 참조를 먼저 검사한다. 진행 중 이동 실패 시 앞서 완료한 이동을 역순으로 복구하며, 파일 접근 문제로 복구까지 실패하면 해당 백업 경로와 오류를 표시한다.
- 상단 `Restore Last Move`는 마지막 드롭에서 실제로 이동한 **묶음 전체**의 타입·데이터·폴더를 복구한다. 이전 단일 이동 기록도 호환된다. 어느 하나라도 이후 수정된 파일/미저장 데이터/충돌/비호환 참조가 있으면 전체 복구 시작 전에 중단한다. 복구 도중 I/O 오류가 발생하면 남은 기록을 보존하고 복구한 개수를 알린다.
- 일반 Ctrl+Z가 파일 타입 변환을 복구하는 기능은 아니다. 위 버튼을 사용한다. 오래된 백업은 폴더에 보관되며, 재이동이 아니라 과거 백업을 적용하려면 이후 변경과 참조를 먼저 점검해야 한다.

## 검증 범위

- 전체 런타임 C# 컴파일: 오류 0 (기존 경고 38).
- 수정한 Item Maker / 변환 유틸리티 / EditMode 테스트 코드의 별도 컴파일: 오류 0. Unity 생성 Editor 프로젝트의 종속 프로젝트 restore가 실패하여 기존 컴파일된 Editor 의존성을 사용한 별도 검사로 검증했다.
- `ItemHandAndCategoryTests`, `ItemMakerBatchTests`: 손 표시·참조 필터·다중 선택·묶음 이동·복구 보호 EditMode 회귀 테스트. 실제 게임 프로젝트의 Test Runner 실행은 별도 확인 필요.
- 임시 Unity 6000.0.47f1 프로젝트에서 실제 생산 변환 유틸리티·손 표시 유틸리티·핵심 SO 소스를 실행해 GUID/localID, 공통 데이터, 살아 있는 SO/씬 참조, 재임포트, 프리팹 변환 유지, 복구 및 비호환 참조 차단을 검증했다. 게임 의존 타입 일부는 최소 계약으로 대체했으므로 전체 게임 플레이 검증을 대신하지 않는다.
- 격리된 다중 선택/일괄 이동 실행: **22개 검사 통과**. Ctrl 토글/드래그 선택 유지/Shift 범위/필터 정리, GUID·참조 보존, 이름 중복과 타입 참조 사전 차단, 강제 중간 이동 실패 시 역순 복구, 저장·미저장 수정 보호, 묶음 기록 및 구형 단일 기록 복구를 포함한다.
- 기존 손 표시/단일 이동/텍스트·바이너리 참조 검증도 변경 후 재실행해 **25개 검사 통과**했다. 두 격리 실행을 합쳐 47개 검증 항목이며, 실제 Item Maker 창의 마우스 이벤트 조작 검증은 포함하지 않는다.
- 기존 작업 프로젝트의 화면 조작이나 사용자 아이템 일괄 변환은 하지 않았다.

실제 Unity에서는 의료품 선택 → 총 숨김/손 모델 표시 → 해제/총 복귀, 물품별 보정, 수류탄 투척, 카드 드래그 및 복구 버튼을 확인할 것.
